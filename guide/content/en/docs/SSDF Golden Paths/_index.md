# NIST Secure Software Development Framework (SSDF) — Overview
The [Secure Software Development Framework](https://nvlpubs.nist.gov/nistpubs/specialpublications/nist.sp.800-218.pdf), defined in NIST SP 800-218, provides a structured set of security practices designed to reduce software vulnerabilities throughout the software development lifecycle (SDLC). Rather than treating security as a final checkpoint before release, SSDF encourages organizations to integrate security into development, build, deployment, and ongoing maintenance activities. The framework establishes four core practice groups: Prepare the Organization (PO), Protect the Software (PS), Produce Well-Secured Software (PW), and Respond to Vulnerabilities (RV). Together, these practices help organizations prevent vulnerabilities, protect software integrity, identify security risks, and respond to vulnerabilities that emerge after release.


# Platform Engineering Golden Paths — Overview

The **CDF Platform Engineering Golden Paths Guide**, developed by the Continuous Delivery Foundation (CDF) Platform Engineering SIG, provides practical guidance for creating reusable, automated, and self-service workflows that simplify software development, delivery, and operations.

Platform Engineering enables organizations to improve developer productivity, reduce operational complexity, and establish consistent practices through internal developer platforms (IDPs). Golden paths provide recommended approaches to common development and operational tasks, allowing teams to adopt proven workflows without independently assembling and maintaining the underlying tools and infrastructure.

The guide organizes golden paths into three phases of the software delivery lifecycle: **Develop and Prepare, Build and Deliver, and Operate and Improve**. Each phase highlights opportunities to standardize workflows, automate repetitive tasks, and integrate open-source tooling to improve the developer experience.

## Phase 1: Develop and Prepare

**Primary objective:** Simplify developer onboarding and provide consistent, self-service environments that accelerate application development.

This phase focuses on giving developers a reliable starting point through standardized application templates, development environments, reusable components, and accessible documentation. Golden paths can streamline repository creation, configuration management, dependency management, and access to shared services. They can also support AI-assisted development and incorporate baseline quality, security, and operational practices, allowing developers to focus on building software rather than managing tools and infrastructure.

## Phase 2: Build and Deliver

**Primary objective:** Provide consistent, automated, and reliable workflows for building, testing, packaging, and deploying applications.

This phase focuses on simplifying software delivery through standardized CI/CD pipelines, automated testing, artifact management, infrastructure provisioning, and reusable deployment workflows. Golden paths can streamline configuration management, release strategies, and rollback while maintaining traceability across builds and deployments. By incorporating quality, reliability, and security checks into shared workflows, platform teams reduce complexity and enable developers to deliver software faster and with greater confidence.

## Phase 3: Operate and Improve

**Primary objective:** Simplify application operations, improve reliability, and enable continuous improvement through shared platform services.

This phase extends golden paths beyond deployment to support ongoing application operations and maintenance. Platform teams can provide standardized workflows for observability, incident response, configuration changes, scaling, software updates, and resource optimization. By providing visibility into application health, service ownership, operational costs, and deployed software, platform teams help developers manage applications more effectively. Continuous feedback and operational metrics allow teams to refine golden paths and improve the developer experience over time.
